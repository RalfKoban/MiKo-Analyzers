# MiKo_3248: Avoid complex expressions in exception helper arguments

## Cause

An argument passed to an exception helper method, such as `ArgumentNullException.ThrowIfNull()` or `ArgumentOutOfRangeException.ThrowIfGreaterThan()`, is a complex expression.

## Rule description

Arguments passed to exception helper methods and similar APIs should be simple expressions.
Using null-coalescing (`??`), conditional access (`?.`), LINQ queries, or other complex expressions obscures the validation logic and makes the code harder to read, understand, and maintain.

## Rationale behind

Exception helper methods exist to validate values in a short and clear way.
The reader should see at a glance which value is checked and which condition causes the exception.

When the argument is a complex expression, the check becomes hard to read.
Expressions with null-coalescing (`??`), conditional access (`?.`), or LINQ queries can hide what is really validated.
They can also change the outcome of the check, for example when a `??` expression turns a `null` value into a non-`null` value, so the validation never fails.

Keeping the arguments simple provides several important benefits:

- **Improved Readability**:
  A simple argument shows directly which value is validated.
  Developers do not have to work out what the expression evaluates to.

- **Clearer Validation Logic**:
  The check and the computation of the value are separate steps.
  This makes it obvious what is validated and why an exception is thrown.

- **Easier Debugging**:
  The computed value can be inspected in the debugger before it is validated.
  Developers can see the exact value that caused an exception.

- **Fewer Hidden Bugs**:
  Complex expressions can change or hide the value that should be checked.
  Simple arguments make sure that the value that is validated is the value that is used later.

- **Better Maintainability**:
  Simple statements are easier to change and to review.
  Changes are less likely to accidentally break the validation.

## How to fix violations

To fix a violation of this rule, perform the required computation or null checks separately.
Then pass the resulting value directly to the exception helper method.

## How to suppress violations

```csharp
#pragma warning disable MiKo_3248
#pragma warning restore MiKo_3248
```
