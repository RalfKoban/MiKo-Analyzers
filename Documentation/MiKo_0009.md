# MiKo_0009: Keep loops small

## Cause

A loop contains too many lines of code.

## Rule description

To make code easier to read and maintain, loops should be kept short.
This follows the Single Responsibility Principle (SRP) and the Single Level of Abstraction (SLoA) principle.

## Rationale behind

Long loops are difficult to understand, test, and maintain.
It is hard to see what is repeated and when the loop ends.
Loop bodies that do many things at once are harder to understand, so mistakes are easier to overlook.

Moving the work of a loop body into well-named methods makes the code easier to follow.

Keeping loops small provides several important benefits:

- **Improved Readability**:
  Short loops can be understood at a glance.
  Developers see directly what is repeated without scrolling through many lines.

- **Easier Testing**:
  Code moved out of a loop body can be tested on its own.
  Fewer test cases are needed to cover the different paths.

- **Better Maintainability**:
  Changes are easier to make when each piece of code has a single purpose.
  Changes are also less likely to break something else.

- **Clearer Intent**:
  A loop that calls a well-named method tells what happens in each iteration.
  The details are placed in that method.

- **Fewer Errors**:
  Small loops make it easier to see mistakes such as wrong exit conditions or misplaced `break` and `continue` statements.

- **Reduced Cognitive Load**:
  Developers do not need to keep many variables and nested conditions in mind.
  This makes it easier to understand how the pieces fit together.

## How to fix violations

To fix a violation of this rule, move parts of the loop body into separate methods.
Each method should have a single responsibility and operate at a single level of abstraction.

Look for natural boundaries in the loop body where functionality can be extracted.
Give the new methods meaningful names that describe what they do.

## How to suppress violations

```csharp
#pragma warning disable MiKo_0009
#pragma warning restore MiKo_0009
```
