# MiKo_1541: Do not prefix parameters with `actual`

## Cause

A parameter name contains `actual` as prefix.

## Rule description

Parameters should not be prefixed with `actual` because that term does not add any value and merely repeats what is already obvious from the surrounding code.
Remove the prefix to keep names concise and easier to read.

## Rationale behind

The word `actual` in a parameter name does not describe what the value represents.
It only restates that the parameter holds a real value, which is already true for every parameter.
This makes the name longer without making it clearer.

Removing the `actual` prefix provides several important benefits:

- **Improved Readability**:
  A name without the `actual` prefix is shorter and easier to scan.
  Readers see the meaning of the value right away, instead of skipping over a word that adds no information.

- **Clearer Intent**:
  A name like `user` describes what the parameter represents.
  A name like `actualUser` does not add any further meaning, so the shorter name communicates the same intent more directly.

- **Consistency Across the Codebase**:
  When the `actual` prefix is avoided everywhere, parameter names follow one consistent style.
  This makes the codebase easier to navigate, because similar values are always named the same way.

- **Less Noise While Reading Code**:
  Extra words in a name increase the mental effort needed to read a line of code.
  Removing unnecessary words reduces this noise and lets the reader focus on the actual logic.

## How to fix violations

To fix a violation of this rule, rename the parameter to remove `actual` from its name.

## How to suppress violations

```csharp
#pragma warning disable MiKo_1541
#pragma warning restore MiKo_1541
```
