# MiKo_3247: Do not assign `null` to collection parameters

## Cause

`null` is assigned to a parameter of a collection, array, or `IEnumerable` type.

## Rule description

Code readability and API usability improve when collection parameters are always represented by a valid collection instance.
Assigning `null` to a collection, array, or `IEnumerable` parameter introduces an additional state that consumers and subsequent code must handle.
Use an empty collection, array, or enumerable instead to make the intent explicit and simplify null handling.

## Rationale behind

A collection parameter that can be `null` has two ways to say "nothing": `null` and an empty collection.
Code that uses the parameter later has to handle both cases.
If one check is forgotten, a `NullReferenceException` occurs at runtime.

Always using a valid collection instance removes this extra state.
An empty collection already expresses "no items" in a clear way.

Using valid collection instances provides several important benefits:

- **Fewer Null Checks**:
  Code that uses the parameter does not need to check for `null` before using it.
  This keeps the code shorter and easier to read.

- **Fewer Runtime Errors**:
  Loops and LINQ calls work on empty collections without any problem.
  The same calls on `null` would throw a `NullReferenceException` or an `ArgumentNullException`.

- **Clearer Intent**:
  An empty collection says directly that there are no items.
  A `null` value leaves open if it means "no items", "not set", or "unknown".

- **Better API Usability**:
  Consumers of the code can rely on getting a usable collection.
  They do not need to read the documentation to learn how `null` is treated.

- **Consistent Code**:
  When collection parameters never receive `null` anywhere in the codebase, the same rule applies everywhere.
  This makes the code easier to understand and to maintain.

## How to fix violations

To fix a violation of this rule, do not assign `null` to the collection parameter.
Assign an empty collection, array, or enumerable instead.

## How to suppress violations

```csharp
#pragma warning disable MiKo_3247
#pragma warning restore MiKo_3247
```
