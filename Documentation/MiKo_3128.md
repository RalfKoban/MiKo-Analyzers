# MiKo_3128: Test methods should be marked as tests

## Cause

A public method contains assertion calls, but the method is not marked with a test attribute.

## Rule description

Methods that are tests should be marked as test methods so that the testing framework can find and run them.

### Rationale behind

A method that calls an assertion (such as one from NUnit, xUnit, or MSTest) is very likely meant to be a test.
If the method is missing the test attribute, the testing framework will not run it.
This means the test is silently skipped, and any bug it should catch stays hidden.

Marking test methods with the correct attribute is important for a test suite to work as intended.

Missing a test attribute has several negative effects:

- **Hidden test gaps**:
  A method without a test attribute is never run by the testing framework.
  The code inside looks like a test, but it provides no real protection against bugs.

- **False sense of safety**:
  Team members may believe a feature is covered by tests, because a test-like method exists.
  In reality, the method never executes, so the feature is not verified at all.

- **Wasted effort**:
  Time was spent writing the test logic and assertions.
  Without the attribute, that effort provides no value, because the test never runs.

- **Harder code reviews**:
  Reviewers expect methods with assertions to be executed as tests.
  A missing attribute is easy to miss during review, especially in large test classes.

Adding the correct test attribute ensures that every intended test is actually executed and can catch real problems.

## How to fix violations

Add the test attribute that matches the testing framework used in the project.
For NUnit, add the `Test` attribute.
For xUnit, add the `Fact` attribute.
For MSTest, add the `TestMethod` attribute.

## How to suppress violations

```csharp
#pragma warning disable MiKo_3128
#pragma warning restore MiKo_3128
```
