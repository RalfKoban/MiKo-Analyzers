# MiKo_3130: Do not call `Assert.Fail` inside condition

## Cause

`Assert.Fail` is invoked inside an `if` statement.

## Rule description

`Assert.Fail` should not be invoked inside an `if` statement.
Instead, `Assert.That` should be invoked asserting the condition of the `if` statement.

### Rationale behind

Using assertion APIs directly for the tested condition makes the intent of a test easier to understand.
Conditional calls to `Assert.Fail` require readers to mentally evaluate the control flow before understanding what is being verified.

Benefits of following this rule:

- **Improved readability**:
  The tested condition is visible directly in the assertion.
  This makes tests easier to read and understand.

- **Clearer test intent**:
  The expected result is expressed explicitly.
  This helps developers quickly understand what the test verifies.

- **Reduced complexity**:
  Additional control-flow statements are avoided.
  Simpler test code is easier to maintain.

- **More consistent test code**:
  Tests follow a common assertion style.
  Consistency makes a test suite easier to navigate and review.

- **Easier maintenance**:
  Test logic remains focused on verification instead of flow control.
  This reduces the effort required when updating tests.

## How to fix violations

To fix a violation of this rule, replace the conditional call to `Assert.Fail` with an assertion that directly verifies the condition.

## How to suppress violations

```csharp
#pragma warning disable MiKo_3130
#pragma warning restore MiKo_3130
```
