# MiKo_3019: Do not throw from dispose-related members

## Cause

A method named `Dispose`, `DisposeCore`, or `DisposeAsync`, or a property named `IsDisposed`, throws an exception directly.

## Rule description

Methods named `Dispose`, `DisposeCore`, or `DisposeAsync` should complete cleanup operations without directly throwing exceptions.
Exceptions from disposal paths can make error handling unreliable and may hide the original failure.

The same applies to properties named `IsDisposed`which should report the disposal state without throwing exceptions.

Keeping these members exception-free makes resource cleanup and state checks more predictable and robust.

## Rationale behind

Disposal is the last step in the life of an object.
Callers expect that cleaning up resources always works and that it can be done safely at any time.
Callers often dispose objects inside `finally` blocks or `using` statements, which run while another error may already be in progress.
If disposal throws as well, the new exception can replace the original one, and the real cause of the failure is lost.

An `IsDisposed` property is used to check the state of an object before it is used.
If such a check throws, it cannot do its job, and callers have no safe way to find out the state.

This is also described in the Microsoft rule [CA1065](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca1065), which lists dispose methods as places where exceptions should not be raised.

Keeping these members free of exceptions provides several important benefits:

- **Reliable Error Handling**:
  The original exception stays visible and is not hidden by a second exception from the cleanup code.
  This makes it much easier to find the real cause of a problem.

- **Safe Resource Cleanup**:
  When disposal does not throw, all remaining resources can still be released.
  This avoids resource leaks such as open files, connections, or handles.

- **Predictable Behavior**:
  Callers can dispose objects, and call `Dispose` multiple times, without having to guard each call with extra error handling.
  This keeps the calling code simple.

- **Dependable State Checks**:
  An `IsDisposed` property that always returns a value can be used anywhere, for example in guard clauses, without causing new failures.

- **Fewer Crashes**:
  Exceptions thrown from finalizers or during cleanup can terminate the application.
  Avoiding them makes applications more stable.

## How to fix violations

To fix a violation of this rule, remove the direct `throw` statements from the reported member.
The member should complete its work and report the disposal state without raising exceptions.

## How to suppress violations

```csharp
#pragma warning disable MiKo_3019
#pragma warning restore MiKo_3019
```
