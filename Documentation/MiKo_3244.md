# MiKo_3244: Replace complex lambda expressions with named methods

## Cause

A lambda expression contains too many lines of code or is too complex.

## Rule description

To make code easier to read and maintain, lambda expressions should be kept short.
Long lambda bodies are difficult to understand and often deserve a meaningful name.
Consider replacing the lambda expression with a named method.

## Rationale behind

Long lambda expressions are difficult to understand, test, and maintain.
They are written inline, so the surrounding code is mixed with the details of the lambda body.
This makes it harder to see what the code around the lambda is doing.

Moving the body into a named method gives the logic a clear name and a clear place.

Keeping lambda expressions small provides several important benefits:

- **Improved Readability**:
  Short lambda expressions can be understood at a glance.
  The code around them stays easy to follow.

- **Easier Testing**:
  A named method can be tested on its own.
  A lambda body that is written inline can only be tested through the code that contains it.

- **Better Maintainability**:
  Changes are easier to make when the logic is in a separate method with a single purpose.
  Changes are also less likely to break something else.

- **Clearer Intent**:
  A good method name tells what the code does.
  The code inside the method shows how it works.

- **Easier Debugging**:
  Named methods are easier to find in stack traces.
  Breakpoints are also easier to set and follow.

- **Enhanced Reusability**:
  A named method can be used in other places.
  This means less duplicate code needs to be written.

## How to fix violations

To fix a violation of this rule, move the body of the lambda expression into a separate named method.
Give the method a meaningful name that describes what it does.

The lambda expression can then be replaced by a call to that method.

## How to suppress violations

```csharp
#pragma warning disable MiKo_3244
#pragma warning restore MiKo_3244
```
