# MiKo_3246: Methods should expose behavior directly

## Cause

A method returns a delegate type, such as `Action`, `Func<T>`, or a custom delegate.

## Rule description

Delegate-returning methods introduce an additional level of indirection that makes code harder to understand and navigate.
Expose operations directly instead of returning delegates that merely expose the same behavior.
This makes APIs easier to use and the intent of the code clearer.

## Rationale behind

Delegate-returning methods often introduce unnecessary indirection.
Readers must first determine which delegate is returned and then trace the operation behind it.

Delegate types express only a method signature, not the intent of the represented behavior.
They do not distinguish between commands, callbacks, predicates, converters, and similar concepts.
As a result, APIs become less self-explanatory and harder to evolve.

This rule targets unnecessary indirection, not delegates themselves.
When an operation already exists as a named method, it should generally be exposed and invoked directly rather than returned through a delegate.

Following this rule provides several important benefits:

- **Less Indirection**:  
  Readers can see immediately what is executed without first tracing a returned delegate.
  The code is easier to follow and navigate.

- **Intent Is Clear**:  
  A delegate type such as `Action` or `Func<T>` describes only a method signature.
  It does not reveal whether it represents a command, callback, validator, filter, converter, or something else.
  Similar to using `string`, `int`, or `Guid` for concepts that deserve dedicated types, delegate types describe structure but not purpose.
   Instead, expose behavior through named methods or dedicated abstractions that make the intent explicit.

- **Easier Usage**:  
  A direct method call is simple to use and clearly shows that an operation is performed.
  Callers do not have to call a method to obtain a delegate and then invoke that delegate.

- **Better Evolvability**:  
  Methods and dedicated abstractions can be extended, documented, and changed more easily than a bare delegate signature.

- **Better Tooling Support**:  
  IDE features such as parameter information, documentation, and navigation work better for methods than for returned delegates.

## How to fix violations

To fix a violation of this rule, expose the behavior directly as a method instead of returning a delegate.

## How to suppress violations

```csharp
#pragma warning disable MiKo_3246
#pragma warning restore MiKo_3246
```
