# MiKo_3245: Properties should not return delegates

## Cause

A property returns a delegate type, such as `Action`, `Func<T>`, or a custom delegate.

## Rule description

Delegate-returning properties blur the distinction between state and behavior.
Instead, expose operations as methods.
This makes APIs more intuitive for callers and the code easier to understand and maintain.

## Rationale behind

Properties are expected to expose state, while methods are expected to perform operations.

Returning a delegate from a property blurs this distinction and makes the API harder to understand.
Callers may assume they are invoking a method when they are actually retrieving a delegate and invoking it.
Replacing delegate-returning properties with methods makes the API clearer.

Following this rule provides several important benefits:

- **Clear API Design**:
  Properties describe what an object is or has, and methods describe what an object does.
  Keeping both apart makes the intent of the API obvious.

- **Intent Is Not Obvious**:
  A delegate type such as `Action` or `Func<T>` describes only a method signature.
  It does not explain the purpose of the behavior.
  Readers cannot easily tell whether the delegate represents a command, callback, validator, filter, converter, or something else.
  Named methods and dedicated abstractions make the intent clearer.

- **Meaningful Types Improve Understanding:**
  Similar to using `string`, `int`, or `Guid` for concepts that deserve their own dedicated types, delegate types describe structure but not meaning.
  More specific APIs help readers understand the code without examining implementation details.

- **Improved Readability**:
  A method call shows directly that an operation is performed.
  Readers do not have to think about what is retrieved and what is invoked.

- **Better Discoverability**:
  Developers look for operations among the methods of a type.
  Operations hidden in properties are easy to miss.

- **Better Tooling Support**:
  IDE features such as parameter info, documentation, and navigation work better for methods.
  Delegates returned from properties often provide less help.

- **Easier Testing**:
  Methods are easier to replace, mock, and verify in unit tests.
  Delegate-returning properties require additional setup to do the same.

- **Fewer Surprises**:
  A property that returns a delegate can return different delegates over time or even `null`.
  This leads to unexpected behavior when the delegate is invoked.

## How to fix violations

To fix a violation of this rule, replace the delegate-returning property with a method that performs the operation.

## How to suppress violations

```csharp
#pragma warning disable MiKo_3245
#pragma warning restore MiKo_3245
```
