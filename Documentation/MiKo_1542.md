# MiKo_1542: Avoid multiple events with the same semantic meaning

## Cause

An interface exposes multiple events that have the same semantic meaning but different names.

## Rule description

Interfaces should not expose multiple events that represent the same lifecycle stage or action using different names.
Similar event names make it unclear when each event is raised and what distinguishes them.
Using a single, consistent event name for each semantic concept makes the code easier to maintain and understand.

## Rationale behind

Events tell other code that something has happened.
Sometimes an interface has several events with different names but the same meaning.
Then developers have to guess whether the events are the same or are raised at different times.

The events might also provide different data, so it is not clear which event to use to get which data.
Developers should not have to read the implementation to find out the difference between two events.

Using one event for each meaning provides several important benefits:

- **Clearer Intent**:
  Each event has one clear meaning.
  Developers know when the event is raised and do not have to remember small differences between similar names.

- **Easier Usage**:
  Developers subscribe to the one event they need and get all the data from it.
  They do not have to wonder which other events they need or which event provides which data.

- **Consistent Implementations**:
  Developers know which event to raise and when.
  No implementation raises only some of the similar events.

- **Better Maintainability**:
  Fewer events mean less code to maintain and test.
  A change has to be made in one place only.

## How to fix violations

To fix a violation of this rule, remove the duplicate events so that only one event remains for each semantic concept.
If the events are raised under different circumstances, rename them so that the names describe the difference clearly.

## How to suppress violations

```csharp
#pragma warning disable MiKo_1542
#pragma warning restore MiKo_1542
```
