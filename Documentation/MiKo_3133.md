# MiKo_3133: Avoid trivial assertion helper methods

## Cause

A helper method in a unit test contains only a single assertion call.

## Rule description

Helper methods that contain only a single `Assert` call do not provide meaningful abstraction.
Keeping the assertion in the test improves readability and reduces indirection.

## Rationale behind

A helper method that only wraps a single assertion adds a new name and a new place to look at, but it adds no real value.
The assertion itself is usually as clear as the helper name, or even clearer.

Readers of the test have to jump to the helper to see what is really checked.
This breaks the flow of reading the test from top to bottom.

Keeping the assertion directly in the test provides several important benefits:

- **Improved Readability**:
  The test shows directly what is expected.
  Readers do not need to open another method to understand the check.

- **Less Indirection**:
  Fewer methods mean fewer places to look at.
  The test stays self-contained and easy to follow.

- **Clearer Failure Messages**:
  When an assertion fails, the failure points directly to the test that contains it.
  With a helper, the failure points to the helper, which is used by many tests.

- **Easier Maintenance**:
  Changing the expectation of one test does not affect other tests.
  A shared helper can accidentally change the behavior of many tests at once.

- **Less Code**:
  There are fewer methods to write, name, and maintain.
  The test code stays small and focused.

## How to fix violations

To fix a violation of this rule, remove the helper method and place the assertion directly into the tests that used it.

## How to suppress violations

```csharp
#pragma warning disable MiKo_3133
#pragma warning restore MiKo_3133
```
