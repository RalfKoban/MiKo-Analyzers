# MiKo_6076: Place type argument lists on single line

## Cause

A type argument list is unnecessarily split across multiple lines.

## Rule description

Type argument lists that span multiple lines are more difficult to read.
Keep type argument lists on a single line to make the code easier to read and follow.

## Rationale behind

A type argument list is the part in angle brackets, such as `<string, int>`.
It is usually short and belongs closely to the generic type or method it describes.

Splitting it across multiple lines separates the type arguments from the name they belong to.
This makes it harder to see which types are used.

Keeping type argument lists on a single line provides several important benefits:

- **Improved Readability**:
  A type argument list on a single line can be read at a glance.
  There is no need to scan multiple lines to find out which types are used.

- **Reduced Visual Clutter**:
  Single-line type argument lists use less vertical space.
  This allows more code to be visible on the screen at once.

- **Clear Association**:
  The type arguments stay next to the generic type or method name.
  This makes it obvious which type arguments belong to which generic.

- **Consistent Code Style**:
  Type argument lists look the same everywhere in the code base.
  This helps developers to find their way around the code faster.

- **Easier Code Maintenance**:
  Type arguments on a single line are easier to change.
  Differences in code reviews are also smaller and easier to understand.

## How to fix violations

To fix a violation of this rule, move the type argument list onto a single line.
Ensure that the type arguments follow directly after the name of the generic type or method.

## How to suppress violations

```csharp
#pragma warning disable MiKo_6076
#pragma warning restore MiKo_6076
```
