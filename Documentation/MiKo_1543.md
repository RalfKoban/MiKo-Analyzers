# MiKo_1543: Type names should match their creation pattern

## Cause

A type is named like a factory or a builder, but it has no methods and only provides properties.

## Rule description

Types named as factories or builders should provide the operation associated with their pattern.
Factories should expose a `Create` method, and builders should expose a `Build` method.

Types that do not provide the expected operation should be renamed to reflect their actual responsibility, such as using a `Provider` suffix when they only expose dependencies.

## Rationale behind

The name of a type tells developers what to expect from it.
A type named as a factory is expected to create objects, and a type named as a builder is expected to build objects step by step.
If the type has no methods and only provides properties, it cannot do this, so the name is misleading.

Such a type only gives access to values or dependencies.
This is the job of a provider, not of a factory or a builder.

Naming such a type as a provider, or with another name that fits its responsibility, provides several important benefits:

- **Clear Responsibility**:
  A name such as `Provider` tells that the type supplies existing values or dependencies.
  Developers see at first glance what the type is for.

- **Correct Expectations**:
  A provider name makes clear that the type gives access to something that already exists.
  Developers do not search for a `Create` or `Build` method and do not expect new objects to be made.

- **Easier Usage**:
  When the name matches the content, developers know that the properties are the way to get what they need.
  This reduces the need to read the type to learn how it is used.

- **Better Discoverability**:
  Developers who look for a place that supplies certain values or dependencies can find a provider by its name.
  The name works like a label that guides them to the right type.

- **Better Communication**:
  Team members and reviewers can talk about the design with precise terms.
  A provider is understood as a supplier of values, which avoids wrong assumptions during discussions and code reviews.

## How to fix violations

To fix a violation of this rule, rename the type so that the name describes what the type really does.
The name should not contain `Factory` or `Builder`.

A name such as `...Provider` is often a good choice for a type that only provides properties.
Any other name that fits the responsibility of the type is fine as well.

## How to suppress violations

```csharp
#pragma warning disable MiKo_1543
#pragma warning restore MiKo_1543
```
