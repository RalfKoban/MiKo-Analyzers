# MiKo_3238: Avoid empty argument lists on initializers

## Cause

An object or collection initializer uses an empty argument list `()`, even though no constructor arguments are needed.

## Rule description

Empty parentheses on initializers add visual noise without providing any value, as no constructor arguments are passed.
Removing them keeps the code concise and easier to read.

### Rationale behind

An empty argument list does not add any information.
It only takes up space and distracts from the actual content of the initializer.

Removing the empty parentheses provides several important benefits:

- **Improved Readability**:
  Without the empty parentheses, the initializer looks cleaner.
  Readers can focus on the important part, which is the initializer content itself.

- **Less Visual Noise**:
  Empty parentheses carry no meaning.
  Removing them reduces clutter and keeps the code tidy.

- **Consistency**:
  Applying this rule everywhere makes the codebase more uniform.
  Developers do not need to wonder why some initializers have empty parentheses and others do not.

- **Clearer Intent**:
  Without the empty parentheses, it is immediately clear that no constructor arguments are being passed.
  This avoids confusion about whether the parentheses are hiding something important.

## How to fix violations

To fix a violation of this rule, remove the empty parentheses after the type name in the initializer.

## How to suppress violations

```csharp
#pragma warning disable MiKo_3238
#pragma warning restore MiKo_3238
```
