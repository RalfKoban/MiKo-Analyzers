# MiKo_6075: Place `ConfigureAwait` on separate line

## Cause

The call to `ConfigureAwait` is placed on the same line as the end of a multi-line awaited method invocation.

## Rule description

When an awaited method invocation spans multiple lines, place the call to `ConfigureAwait` on its own line.
This makes the code easier to read and keeps the invocation and continuation chain clearly separated.
Align the call with the start of the method chain to maintain consistent formatting.

## Rationale behind

When an awaited call spans multiple lines, a `ConfigureAwait` at the end of the last line is easy to overlook.
It looks like a part of the last argument or the last chained call, although it controls how the await continues.

Placing `ConfigureAwait` on its own line makes this difference visible.

Following this rule provides several important benefits:

- **Improved Readability**:
  The call to `ConfigureAwait` is easy to find at a glance.
  Developers do not need to search at the end of a long line.

- **Clear Separation**:
  The method invocation and the await configuration are separated.
  This shows that `ConfigureAwait` is not part of the actual work done by the invoked method.

- **Consistent Formatting**:
  All multi-line awaited calls look the same.
  This makes the code easier to scan and to review.

- **Easier Changes**:
  The call can be changed or removed without touching the lines of the invocation.
  This keeps differences in version control small and easy to understand.

## How to fix violations

To fix a violation of this rule, move the call to `ConfigureAwait` to its own line.
Align it with the start of the method chain.

## How to suppress violations

```csharp
#pragma warning disable MiKo_6075
#pragma warning restore MiKo_6075
```
