# MiKo_6081: Align open brace vertically with the start of its code construct

## Cause

An opening brace is not in the same column as the start of its code construct.

## Rule description

Code readability improves when the opening brace of a namespace, type, member, or statement is vertically aligned with the start of the code construct it belongs to.
This makes the structure clearer and easier to scan.

## Rationale behind

The opening brace marks the start of the body of a code construct.
When it is placed in a different column than the start of that code construct, it is harder to see which code construct the body belongs to.
This makes the code harder to read and increases the risk of mistakes.

Aligning the opening brace with the start of its code construct provides several important benefits:

- **Improved Readability**:
  The code construct and its opening brace form a clear visual unit.
  Developers see the scope of the code construct at a glance.

- **Easier Navigation**:
  Developers can follow a vertical line from the start of the code construct via the opening brace to the closing brace.
  This helps to find the start and end of the body quickly.

- **Fewer Mistakes**:
  Misplaced braces are easier to spot when the layout is consistent.
  This reduces errors when code is changed or new statements are added to a body.

- **Consistent Code Style**:
  A uniform layout makes all code in a code base look the same.
  This helps developers to feel familiar with code written by others.

- **Simpler Code Reviews**:
  Reviewers can focus on the logic instead of the formatting.
  Structural problems are visible more quickly.

## How to fix violations

To fix a violation of this rule, place the opening brace at the same indentation level as the first token of the code construct it belongs to.
The code fix provider does this automatically.

## How to suppress violations

```csharp
#pragma warning disable MiKo_6081
#pragma warning restore MiKo_6081
```
