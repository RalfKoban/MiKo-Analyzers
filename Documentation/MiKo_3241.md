# MiKo_3241: Task-returning methods should be cancelable

## Cause

A method returns `Task` or `Task<T>` but has no `CancellationToken` parameter.

## Rule description

Methods that return `Task` or `Task<T>` should be cancelable.
Such methods should therefore declare a `CancellationToken` parameter so callers can cancel the operation when needed.

## Rationale behind

Methods that return a `Task` often run for a longer time.
They may wait for a database, a network call, or a file.

Without a `CancellationToken`, the caller has no way to stop such an operation.
The operation keeps running even if the result is not needed anymore.

Making these methods cancelable provides several important benefits:

- **Support for Timeouts**:
  A `CancellationToken` can be canceled after a given time.
  This allows callers to stop operations that take too long.

- **Better Responsiveness**:
  Operations can be stopped as soon as the user closes a window or cancels an action.
  The application does not stay busy with work that nobody waits for.

- **Efficient Use of Resources**:
  Canceled operations free threads, connections, and memory early.
  This avoids waste, especially when many operations run at the same time.

- **Easier Composition**:
  A cancelable method can pass its token to other asynchronous methods.
  This way, a single cancellation request stops the whole chain of operations.

- **Consistent API Design**:
  Most asynchronous .NET APIs accept a `CancellationToken`.
  Following the same pattern makes methods familiar and predictable for other developers.

- **Safe Shutdown**:
  Long-running work can be stopped in a controlled way when the application shuts down.

## How to fix violations

To fix a violation of this rule, add a `CancellationToken` parameter to the method.
The parameter is usually the last one in the parameter list.

## How to suppress violations

```csharp
#pragma warning disable MiKo_3241
#pragma warning restore MiKo_3241
```
