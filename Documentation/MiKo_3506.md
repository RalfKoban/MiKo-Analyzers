# MiKo_3506: Empty statements are misleading

## Cause

An empty statement (a single semicolon) is used as the body of a construct that controls the execution of the following code.

## Rule description

Empty statements can cause misleading control flow and introduce logic errors.
Developers often expect the following statement or block to be executed conditionally or repeatedly, but the empty statement becomes the actual body instead.

## Rationale behind

An empty statement is a single semicolon that does nothing, so it is easy to overlook.
Most of the time, it is harmless.

It becomes dangerous when it is the body of a construct that developers expect to control the following code.
Examples are `if`, `for`, `foreach`, `while`, `using`, `lock` and `fixed`.
In such a case, a single misplaced semicolon changes the meaning of the code.

The code still compiles, and it looks as if the following statement belongs to the construct because of its indentation.
In reality, the following statement is not controlled by the construct and is always executed.

Avoiding empty statements as bodies provides several important benefits:

- **Fewer Hidden Bugs**:
  A misplaced semicolon creates a bug that is hard to see during reading and code reviews.
  Compilers and tests often do not detect it.

- **Correct Control Flow**:
  The code behaves the way it looks.
  Conditions, loops and other constructs control the statements that developers expect them to control.

- **Clearer Intent**:
  Other developers can see directly what the code should do.
  An intentionally empty body is clearly visible, and an accidental one is found early.

- **Easier Maintenance**:
  Developers do not need to wonder if a semicolon is a mistake or was added on purpose.
  This reduces the risk of introducing errors when changing the code later.

## How to fix violations

To fix a violation of this rule, remove the empty statement or replace it with the code that should be executed as the body of the construct.

- If the empty body is intended, use an empty block `{ }` instead, and add a comment inside that explains why it is empty so that other developers know it is not empty by accident.

- If the semicolon was added by mistake, the code that follows should be checked to see if it belongs to the construct.

## How to suppress violations

```csharp
#pragma warning disable MiKo_3506
#pragma warning restore MiKo_3506
```
