# MiKo_3236: Use alias instead of fully qualified names

## Cause

A type is referenced by its fully qualified name, even though a shorter alias could be used instead.

## Rule description

Qualified names can make code longer and harder to read.
Use an alias for types with long namespace names to keep declarations short and easier to understand.
This helps improve code readability and reduces visual noise.

### Rationale behind

Fully qualified names repeat the complete namespace path every time a type is used.
This adds extra characters that do not carry much meaning for the reader.
It also makes lines longer, which can force code to wrap or scroll horizontally.

An alias replaces the long namespace path with a short, meaningful name.
The reader only sees the part of the name that matters, without the surrounding noise.

Using an alias instead of a fully qualified name provides several important benefits:

- **Improved Readability**:
  Shorter names are easier to read and scan.
  The reader can focus on the logic of the code instead of parsing long namespace paths.

- **Reduced Visual Noise**:
  Long qualified names clutter the code.
  An alias removes this clutter and keeps the declaration clean.

- **Shorter Lines**:
  Fully qualified names can make lines very long.
  An alias keeps lines short, which reduces the need for wrapping or horizontal scrolling.

- **Easier Maintenance**:
  When an alias is defined once, it can be reused everywhere in the file.
  Changes to the namespace only need to be made in one place.

- **Clearer Intent**:
  A well-chosen alias can describe the purpose of a type more clearly than its fully qualified name.
  This helps other developers understand the code faster.

## How to fix violations

To fix a violation of this rule, define an alias for the type and use that alias instead of the fully qualified name.

## How to suppress violations

```csharp
#pragma warning disable MiKo_3236
#pragma warning restore MiKo_3236
```
