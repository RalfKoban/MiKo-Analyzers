# MiKo_2243: Do not use prefixes in `cref` tags

## Cause

A `cref` tag in the XML documentation uses a prefix, such as `T:`, `M:`, or `P:`.

## Rule description

The `cref` attribute in XML documentation references a code element such as a type, method, or property.
Using prefixes prevents the compiler from validating the reference and stops Visual Studio from updating it during refactorings.

## Rationale behind

A prefix in a `cref` tag is a short code that tells what kind of element is referenced, such as `T:` for a type or `M:` for a method.
While this looks technical and precise, it actually removes some helpful features that come with plain references.

Avoiding prefixes in `cref` tags provides several important benefits:

- **Compiler Validation**:
  Without a prefix, the compiler can check that the referenced element really exists.
  This helps to catch broken references early, before they cause confusion for readers.

- **Automatic Updates During Refactoring**:
  Visual Studio can find and update plain references automatically when a type, method, or property is renamed or moved.
  A prefixed reference is treated as plain text and is not updated, so it can silently become outdated.

- **Simpler and Cleaner Documentation**:
  A reference without a prefix is easier to read, because it only shows the name of the element, without extra technical codes.

- **Fewer Broken Links**:
  Since the compiler checks plain references, mistakes such as typos or outdated names are noticed right away instead of staying hidden in the documentation.

## How to fix violations

To fix a violation of this rule, remove the prefix from the `cref` tag and keep only the plain reference to the type, method, or property.

## How to suppress violations

```csharp
#pragma warning disable MiKo_2243
#pragma warning restore MiKo_2243
```
