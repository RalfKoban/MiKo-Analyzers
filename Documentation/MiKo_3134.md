# MiKo_3134: Do not statically import assertion members

## Cause

A test file statically imports assertion members, for example via a `using static` directive for an assertion type.

## Rule description

Tests are easier to read when assertion members are referenced through their declaring type instead of being statically imported.
Explicit qualification makes assertion calls immediately recognizable.
This improves readability and maintainability.

## Rationale behind

When assertion members are statically imported, calls such as `AreEqual` or `IsTrue` appear without any type name.
A reader then has to look at the `using` directives to find out where the member comes from.
These names can also look like normal methods of the test class.

Assertion calls that are qualified with their declaring type are easy to spot.
The type name makes clear that a check is done and which assertion library is used.

Following this rule provides several important benefits:

- **Improved Readability**:
  Assertion calls stand out from the other code in a test.
  Readers see at a glance which lines verify results.

- **Clear Origin**:
  The declaring type shows where an assertion comes from.
  No search in the `using` directives is needed.

- **Fewer Naming Conflicts**:
  Statically imported members can clash with other members that have the same name.
  Qualified calls avoid such confusion.

- **Better Maintainability**:
  Tests that use different assertion libraries stay easy to understand.
  Changing or reviewing assertions is simpler when the type is always visible.

- **Consistent Style**:
  All tests in a code base look the same.
  This helps developers who are new to the project to find their way.

## How to fix violations

To fix a violation of this rule, remove the static import of the assertion type.
Then reference the assertion members through their declaring type.

## How to suppress violations

```csharp
#pragma warning disable MiKo_3134
#pragma warning restore MiKo_3134
```
