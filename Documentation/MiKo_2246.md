# MiKo_2246: XML documentation should not contain unnecessary indentation

## Cause

An XML documentation text starts with more than one whitespace character.

## Rule description

XML documentation text should not contain unnecessary leading spaces.
Extra indentation inside documentation comments does not improve the generated documentation, but it makes the source code harder to read and maintain.

## Rationale behind

Extra leading spaces inside documentation comments do not change the generated documentation output.
They only add clutter to the source code.

Avoiding unnecessary indentation in documentation comments provides several important benefits:

- **Improved Readability**:
  Documentation comments without extra spaces are easier to scan and read directly in the source code.

- **Consistent Formatting**:
  A single space after the documentation comment marker (`///`) keeps the formatting consistent across the whole codebase.

- **Easier Maintenance**:
  Documentation without stray whitespace is easier to edit and compare, for example when reviewing changes in source control.

- **Cleaner Diffs**:
  Unnecessary spaces can cause unrelated changes to show up in diffs, which makes code reviews harder.

## How to fix violations

Remove the extra spaces and keep only a single space after the documentation comment marker (`///`).

## How to suppress violations

```csharp
#pragma warning disable MiKo_2246
#pragma warning restore MiKo_2246
```
