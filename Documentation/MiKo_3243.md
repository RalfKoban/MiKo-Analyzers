# MiKo_3243: Avoid `do/while` loops

## Cause

A `do/while` loop is used.

## Rule description

`do/while` loops evaluate their condition after the loop body.
That makes the control flow harder to follow, especially in combination with `continue`.
Prefer `while` or `for` loops, where the condition is visible up front.
This makes the code easier to read and maintain.

## Rationale behind

When reading a loop, the first question is usually when it stops.
With a `do/while` loop, the answer is hidden at the very end.
Developers have to read the whole loop body before they find out whether the loop continues or terminates.

Statements such as `continue` make this even harder.
In a `do/while` loop, a `continue` does not go back to the start of the loop body.
Instead, it jumps down to the condition, which is often not what developers expect.

The following code is only shown for demonstration purposes:

```csharp
do
{
    continue;
}
while (false);
```

Does this loop run forever, or does it stop?
It is not obvious at first glance, but it stops after one run (because the condition is `false`).

Avoiding `do/while` loops provides several important benefits:

- **Improved Readability**:
  The condition is visible before the loop body.
  Readers see right away when the loop runs and when it ends.

- **Clearer Control Flow**:
  With `while` and `for` loops, it is clear that a `continue` goes back to the loop condition at the top.
  There is no need to look at the end of the loop to find out what happens next.

- **Easier Maintenance**:
  When the condition is visible at the top, it is easier to see which values change it.
  Changes to the loop are therefore less likely to cause endless loops or skipped iterations.

- **Familiar Loop Style**:
  `while` and `for` loops are used much more often than `do/while` loops.
  Most developers know them well and read them faster.

## How to fix violations

To fix a violation of this rule, replace the `do/while` loop with a `while` loop or another loop construct.
The condition of the new loop should be visible before the loop body.

## How to suppress violations

```csharp
#pragma warning disable MiKo_3243
#pragma warning restore MiKo_3243
```
